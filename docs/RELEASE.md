# Releases

GitHub Actions is the only release path. It publishes separate self-signed
`arm64` and `x86_64` ZIP files, each with a matching signed Sparkle appcast.
Local builds are for development and validation only.

## GitHub Releases

Push a tag in `vX.Y.Z` form to publish a release:

```sh
git tag v0.1.0
git push origin v0.1.0
```

The workflow requires these repository secrets:

- `GALAXY_SELF_SIGN_P12_BASE64`: base64-encoded PKCS#12 file for the persistent `Galaxy Self-Signed` certificate.
- `GALAXY_SELF_SIGN_P12_PASSWORD`: password for that PKCS#12 file.
- `SPARKLE_PRIVATE_KEY`: private EdDSA key generated by Sparkle's `generate_keys` tool.

It also requires the repository variable `SPARKLE_PUBLIC_KEY`, the public EdDSA
key paired with `SPARKLE_PRIVATE_KEY`. Keep private material out of the
repository.

Self-signed distribution requires users to bypass Gatekeeper on their first
install. Subsequent Sparkle updates preserve the same application identity.

## Signing Setup

Configure secrets once on the macOS machine that will retain the signing backup:

```sh
bash scripts/configure-release-secrets.sh adityadarma/galaxy
```

The script invokes `scripts/make-signing-cert.sh` when no PKCS#12 backup exists.
That script only creates/imports the 20-year `Galaxy Self-Signed` identity and
stores its certificate backup. The configuration script creates or exports the
Sparkle EdDSA pair, then uploads the three GitHub Secrets and public Actions
variable.

Private backup files are stored under `~/.galaxy-signing`. Copy that directory
to encrypted offline storage. Scripts do not print private keys or passwords.

Verify the configured names without revealing secret values:

```sh
gh secret list --repo adityadarma/galaxy
gh variable list --repo adityadarma/galaxy
```

Do not rotate `Galaxy Self-Signed` or the Sparkle key pair after users receive
a release. Existing installations trust those identities for application
permissions and Sparkle updates. If the certificate backup is missing while the
identity is still in Keychain Access, export the existing identity as a `.p12`
instead of creating a replacement; save its password in
`~/.galaxy-signing/galaxy-signing.p12.password` and rerun the setup script.

If a private key leaks, use a new release channel and instruct existing users
to install it manually; old builds cannot trust a replacement Sparkle key.

## Sparkle

Sparkle 2.10.0 is embedded through Swift Package Manager. Release builds inject
the public EdDSA key and use architecture-specific feeds:

```text
https://github.com/adityadarma/galaxy/releases/latest/download/appcast-arm64.xml
https://github.com/adityadarma/galaxy/releases/latest/download/appcast-x86_64.xml
```

Local builds have no public key, so update checks remain disabled. The appcast
and each ZIP enclosure are both EdDSA-signed before publishing.

For closed-beta distribution and tester acceptance, use `docs/BETA-README.md`,
`docs/BETA-FEEDBACK.md`, and `docs/BETA-TRIAGE.md`.
