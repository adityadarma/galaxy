## M2 — Workspace and Navigation (3 weeks)

- [x] M2-01 — `Workspace` in Rust: walk with the `ignore` crate, path interning in an arena.
  - Index 100k files < 1 s, index RAM < 20 MB.
  - Status: `build_file_index` scans files (not directories) with the same ignore rules as the Explorer and stores paths as interned component IDs in `PathArena`; opening a workspace stays lazy. Symlinks to folders are not indexed (not followed). `workspace-index` on a synthetic 100,001-file repo (Release, three runs): 622–823 ms, estimated 12.3 MB. The old estimate of 10.82 MB was too low because component names are stored twice (vector and map key); both are now counted. Used by Go to File (M2-07) via `Workspace.build_file_finder`.
- [x] M2-02 — `notify` file watcher (FSEvents) with debounce, updating the index and open buffers.
  - Status: `watcher.rs` uses `notify` 8.2.0 (CC0-1.0, FSEvents backend only). One recursive watcher per window, started when a folder is opened and stopped when the window closes or the folder changes. Events are batched: sent after 60 ms without new events, at most 300 ms after the first event; 200 files at once arrive in ≤ 5 batches. Paths in `.git`, built-in excluded folders, and atomic-save temp files (`.galaxy-*.tmp`) are dropped here; `.gitignore` rules are applied by `Workspace::index_delta`, which checks the disk. Lost events, changes to the root, or batches > 1,000 paths trigger a rescan (rebuild the index and Explorer). The Go to File index is updated in place (`FileFinder::apply_delta`, ~19 ms for 100k files, in the background); recency and context are kept; ⌘P no longer rebuilds the index. The Explorer is re-listed only when a change touches a folder that has already been expanded; expanded folders, selection, and scroll position are preserved. Open buffers are handled in M2-03. Covered by Rust tests (`watcher`, `index_delta`, `apply_delta`, FFI) and `QuickOpenTests`/`ExplorerTests`; not yet tried with a large `git checkout`.
- [x] M2-03 — External change handling: auto-reload when the buffer is clean, conflict prompt when dirty.
  - Status: each document stores a `DiskStamp` (size, mtime, content hash) when opened and saved; Galaxy's own saves are not detected as changes. Checks run on watcher batches (files in the workspace) and when the window becomes key (also files outside the workspace); an unchanged file costs a single `stat`, and a `touch` or checkout with identical content is not treated as a change. Clean buffers are reloaded automatically, including background tabs: only the differing part is replaced (common prefix/suffix kept), as one undo step, with encoding/BOM/line ending following the file. Dirty buffers: a "Keep My Changes" / "Reload from Disk" prompt, asked once when the tab is shown and the window is active; Keep leaves the buffer unsaved relative to the new file. Save checks the disk first and asks for confirmation before overwriting. Deleted files: the tab is titled "(deleted)", the text stays, and it counts as unsaved; Save recreates it, and a file restored with identical content becomes clean again. Covered by Rust tests (`disk`, `reload`, FFI) and `DiskChangeTests`. A rename outside the editor shows as "(deleted)"; the tab does not follow the new name.
- [x] M2-04 — Explorer `NSOutlineView` with per-directory lazy loading, file type icons, dirty status.
  - Status: lazy loading, file type icons, click to open (preview), double-click to pin. A copper dot at the right of the row for unsaved files, and also on the folders that contain them; the accessibility label says "unsaved changes". Covered by `ExplorerTests` and `NavigationFollowUpTests`; not yet tried manually.
- [x] M2-05 — File operations: new, rename, delete to Trash, reveal in Finder, copy path.
  - Status: New File/Folder via header buttons and a name dialog (`/` creates subfolders, never overwrites). In-place rename: Return in the Explorer or the "Rename…" menu turns the row name into a field with the name selected up to the extension; Return/clicking outside saves, Escape cancels. `Workspace::rename` does not overwrite other files, rejects `..`/absolute paths and moving a folder into itself, and allows case-only renames. Open tabs (including files inside a renamed folder) follow the new path along with unsaved edits, as do the recent list and the Go to File index. Delete: ⌘⌫ or "Move to Trash" with confirmation, via `FileManager.trashItem`; clean tabs are closed, tabs with edits stay open as "(deleted)". The context menu selects the row without opening it: New File/Folder, Reveal in Finder, Copy Path, Copy Relative Path, Rename, Move to Trash (the last two only for rows, not empty space). All are in the command palette. Covered by Rust tests (`rename`) and `ExplorerFileOpsTests`; tests use a plain delete instead of Trash, so the real Trash and right-clicking with a mouse have not been tried.
- [x] M2-06 — Tab bar: open, close, reorder, preview tab (single click), dirty indicator, save prompt.
  - Status: tabs are in the title bar row (`TabBar.swift`), with the path bar below. A single click in the Explorer opens a preview tab (italic title) that the next click replaces; an edit or double-click pins it. Files already open are not duplicated. A copper dot replaces the close button on unsaved tabs. ⌘W closes the tab, ⇧⌘W closes the window, ⇧⌘[ / ⇧⌘] switches tabs, drag to reorder, middle-click to close. Closing a window asks about each unsaved tab in turn. Scroll position is stored per tab. Covered by `TabTests`; drag and hover not yet tried with a real mouse.
- [x] M2-07 — Go to File `Cmd+P` with `nucleo`, recency + path proximity ranking, matched-character highlighting.
  - Status: `file_finder.rs` uses `nucleo-matcher` 0.3.1 (MPL-2.0) with path configuration and smart case; multiple words must all match. Ranking: fuzzy score + bonus for matches in the file name + recency (last 50 files) + folder proximity to the active file; ties are broken by shortest path, then alphabetically. A query that extends the previous query only filters the previous results; above 8,192 files the search is split across up to 8 threads. Paths are stored in a single `String` (4.6 MB for 100k files). `file-finder` bench (Release, 100k synthetic paths, 68 keystrokes, three runs): median 1.5 ms, p95 13.9–14.7 ms, max 17.1–17.9 ms; repo_10k on disk: max 3.6 ms. The ⌘P panel (`QuickOpen.swift`) is built on first use; the index is built in the background when a folder is opened and updated by the file watcher (M2-02). Above 20k files, per-keystroke search runs in the background. Covered by `QuickOpenTests` and Rust tests; not yet tried with a real keyboard.
  - < 30 ms per keystroke on 100k files.
- [x] M2-08 — Go to line `Ctrl+G`, back/forward navigation history.
  - Status: `navigation.rs` contains the input parser (`42`, `42:7`, `42,7`, `:42`, `-1` = last line, out-of-range values clamped) and `NavHistory` (max 50 entries per direction, positions ≤ 10 lines apart in the same document are merged, a new jump clears forward history). The ⌃G panel (`GoToLine.swift`) is built on first use; without a column, the caret goes to the first non-whitespace character; off-screen lines are scrolled to the center. Recorded jumps: Go to Line, tab switch, file open, closing the active tab, find (the position when the find bar opens, once per session, plus distant Find Next/Previous), and plain clicks more than 10 lines away. Back reopens files whose tab was closed; closed Untitled buffers are skipped. ⌃- / ⌃⇧- are captured by the window key monitor (Shift turns `-` into `_`, so a menu key equivalent is not enough). ⌃Tab (PRD 7.4) switches to the last viewed tab; pressing it again switches back. Covered by Rust tests, `GoToLineTests`, and `NavigationFollowUpTests`; the key monitor has not been tried with a real keyboard.
- [x] M2-09 — Command registry in Rust + command palette `Cmd+Shift+P`.
  - Status: `commands.rs` contains the registry (unique VSCode-style IDs, category, title, hidden keywords), 36 built-in commands, and `nucleo-matcher` fuzzy search on the `Category: Title` label (keywords only find; they rank below label matches), with a bonus for the 20 most recent commands; empty query: most recently used first, then alphabetical. The ⇧⌘P panel (`CommandPalette.swift`) is built on first use and shows shortcuts from the menu and only the commands that can run at that moment (same validation as the menu). Commands run from the responder that had focus before the palette opened. Tests ensure every command has an action, every menu item has a command, and no action is shadowed by an AppKit method. Finding: `toggleSidebar:`, `selectNextTab:`, `selectPreviousTab:` are already owned by `NSWindow`, which comes earlier in the responder chain, so ⌘B and ⇧⌘[ / ⇧⌘] from the menu probably never reached the controller; all three were renamed. Covered by Rust tests and `CommandPaletteTests`; not yet tried with a real keyboard.
- [x] M2-10 — Default keymap (VSCode-like) and `keybindings.json` overrides.
  - Status: defaults in `keymap.rs` (VSCode macOS shortcuts for all existing commands). The file `~/Library/Application Support/Galaxy/User/keybindings.json` uses the VSCode format: `{ "key", "command" }` adds a binding and takes that key from other commands, `"-command"` removes a default (one key, or all if `key` is empty). Comments and trailing commas are accepted (own JSONC parser, `jsonc.rs`, no new dependency). Invalid entries are skipped with a per-entry message (line/column for a corrupt file, which falls back to defaults); `when`, `args`, and chords are not yet supported and are reported. All shortcuts go through one key monitor per window and run only when their menu item is enabled; the menu and command palette show each command's primary key. "Keyboard Shortcuts…" (View menu and palette) opens the file, created with all defaults as comments; saving applies it immediately, and the file is also re-read when the window becomes active. Covered by Rust tests (`jsonc`, `keymap`) and `KeybindingsTests`; not yet tried with a real keyboard or non-US layouts.
- [x] M2-11 — Session restore: last workspace, tabs, cursor position, scroll.

On launch without a path, the session is restored; missing folders or files are skipped, and the caret is clamped. If nothing is restored, an Untitled buffer opens as usual. Untitled buffers and unsaved edits are not included (closing already prompts for them). A corrupt session file or a different version is ignored with a log entry. Disabled for benchmarks, the unit test host, and `-RestoreSession NO` (UI tests). Covered by `SessionTests`; a real app restart has not been tried by hand, and the effect on the startup budget has not been measured with a large session.

Covered by `GalaxyCLITests`; opening the real app from the helper is not tested automatically so tests do not disturb the desktop.

## M3 — Syntax Highlighting (3 weeks)

- [x] M3-01 — `SyntaxService`: per-document tree-sitter parser on a worker thread, input via rope chunks.
  - Status: `syntax.rs` provides a per-document `SyntaxService` with a Tree-sitter parser on the `galaxy-syntax` thread; submit only clones the `Rope` handle in O(1), parser input is read via `Rope::chunk_at_byte`, and poll does not block. Results carry a revision and only the tree for the latest request is published, so stale parses are discarded. Grammars, queries/captures, and viewport styles/FFI were added in M3-03, M3-04, and M3-05, which connect the service to the renderer. `tree-sitter-json` is only a dev dependency for worker tests, not a production grammar. Covered by rope parse and stale revision tests.
- [x] M3-02 — Incremental parse with `InputEdit` from every edit; document version to discard stale results.
  - Status: `SyntaxEdit` computes byte ranges and Tree-sitter `Point`s directly from the old/new Rope, including UTF-8 and multiline. The worker keeps the last revision's tree, applies `Tree::edit(InputEdit)`, then passes that tree to the parser as the old tree only if `base_revision` matches exactly; a lagging worker or unchained edits fall back to a full parse. Results are still published only for the latest revision. The API supports one contiguous change; when grammars are connected (M3-03), multi-cursor transactions need to send chained edits or fall back to a full parse. Covered by UTF-8/multiline incremental tests and an unchained-revision fallback test; a 10k-line benchmark has not been added yet.
  - Re-parse after an edit < 2 ms on a 10k-line file.
- [x] M3-03 — Bundle grammars: Rust, TS, TSX, JS, JSON, TOML, YAML, Markdown, Python, Go, HTML, CSS, Bash.
  - Status: 13 Tree-sitter grammars are statically pinned in `galaxy-core`; `SyntaxLanguage` is a type-safe registry for Rust, TypeScript, TSX, JavaScript, JSON, TOML, YAML, Markdown, Python, Go, HTML, CSS, and Bash, each with a display name and `Language`. TOML uses `tree-sitter-toml-ng` and Markdown uses `tree-sitter-md-025`, because the standard-name crates still use the old Tree-sitter API. Path/shebang mapping is intentionally M3-06; highlight queries are M3-04. Covered by tests that load every grammar into a parser and parse minimal source without errors.
- [x] M3-04 — Per-language highlight queries, mapping captures to theme scopes.
  - Status: `SyntaxLanguage::highlight_query` uses built-in queries compiled against each grammar. TypeScript/TSX now use Galaxy's internal query because the upstream crate query only covers types/keywords; the internal query covers comment, string/template, number, function/call, property, variable, type, keyword, operator, and punctuation. JavaScript and Bash also use local queries. Captures are mapped to a stable `HighlightScope`: attribute, comment, constant, constructor, function, keyword, label, number, operator, property, punctuation, string, tag, type, and variable. Covered by compiling all queries and by tests on real TypeScript tokens.
- [x] M3-05 — Produce style runs only for the viewport + margin, included in `ViewportSnapshot`.
  - Status: `style_runs_for_viewport` runs the query on the viewport byte range plus 10 lines on each side, then splits the results per display line and converts columns to UTF-16. `Editor::viewport_with_syntax` accepts a finished background tree, so it never parses or blocks the draw path. `ViewportSnapshot.styles` and the FFI record `StyleRun` carry the line, UTF-16 start/end, and stable theme scope. Regular snapshots keep `styles` empty until M3-06 detects the language and attaches a per-document `SyntaxService`; the renderer only uses colors in M3-07. Covered by margin, scope, and Unicode UTF-16 boundary tests.
- [x] M3-06 — Language detection from extension, file name, and shebang.
  - Status: `SyntaxLanguage::detect` in the core recognizes bundled grammar extensions, `Cargo.toml`, and `bash`/`sh`/`zsh`, `python`/`python3`, `node`/`deno` shebangs. `DocumentHandle` attaches a `SyntaxService` per supported non-large file, submits initially and after edits/reloads/path changes, then `viewport()` polls without blocking and only uses a tree whose revision matches. `EditorView` keeps the display link alive until parsing finishes so the next redraw receives styles; the status bar uses the core language when available. Large files and languages without a grammar do not start a parser. UI languages such as Swift still appear as a status label but are not parsed until their grammar is bundled. Covered by detection tests and an FFI async style test for Rust vs plain text.
- [x] M3-07 — JSON theme system, built-in light + dark themes, following macOS appearance.
  - Status: `Galaxy Light.json` and `Galaxy Dark.json` bundle sRGB palettes for every `HighlightScope`; `Theme` loads the JSON once, picks colors via `effectiveAppearance`, and falls back to `textColor` if a resource is corrupt. `EditorView` creates attributed CTLines only for lines that carry `StyleRun`s; the cached plain layout remains for normal lines, hit-testing, gutter, and scrolling. Appearance changes invalidate and redraw so syntax colors update. Covered by `SyntaxThemeTests` (palette scopes and Core Text attributes); not yet verified by screenshot/manually in light or dark mode.
- [x] M3-08 — Bracket matching, indent guides, syntax-based auto-close for brackets/quotes.
  - Status: normal typing pairs `()`, `[]`, `{}`, `''`, and `""` in one undo transaction, wraps selections, and skips over existing closing delimiters; apostrophes inside words and IME commits/replacements are not paired. Snapshots carry indent guides from leading whitespace (tab-expanded) and two bracket-match cells for an empty caret next to `()[]{}`; the renderer draws both below selection/text. The structural bracket scan is capped at 100k characters to keep frames bounded. Tree-sitter is not yet used to distinguish brackets in strings/comments, and language-specific template/string pairing is not done, because the async tree can lag one revision; this needs follow-up work once the parser cache is stable. Covered by core pairing/guide/match tests and `TextInputTests`; a real IME has not been tried.
- [x] M3-09 — Comment toggle based on language config.
  - Status: `SyntaxLanguage` provides line-comment markers for Rust/TypeScript/TSX/JavaScript/Go (`//`) and TOML/YAML/Python/Bash (`#`). `ToggleComment` adds or removes the marker after the indent on every selected line as one undo transaction, available from Edit > Toggle Line Comment and `Cmd+/`. Languages without line comments (JSON, HTML, CSS, Markdown) are a no-op so they do not produce broken source; block comment toggling is deferred. Covered by core marker tests, a multi-line round trip, and the `.rs` input action.
- [x] M3-10 — Symbol outline via tree-sitter `tags.scm` for `Cmd+Shift+O`.
  - Status: the completed syntax tree produces `OutlineSymbol`s from the upstream `tags.scm` for Rust, TypeScript/TSX, JavaScript, Python, and Go. The query runs only when the outline is requested, from the current revision's tree; it does not start a parse or block the editor. Symbols are deduplicated per location for overlapping Rust queries. Go > Go to Symbol, `Cmd+Shift+O`, and the command palette open a picker that filters by name, shows kind/line, then moves the caret with navigation history. Languages without a tag query show an empty outline. Covered by Rust query tests, the async FFI API, and picker filtering/selection tests.
- [x] M3-11 — Drop syntax trees for tabs inactive > 5 minutes; measure RAM savings.
  - Status: tabs record when they were last active. A per-minute timer calls `suspend_syntax()` for tabs inactive for at least five minutes, which drops the `SyntaxService` along with its parser worker and completed Tree; the document Rope, selection, and undo history stay resident. When the tab is selected, `resume_syntax()` creates a new worker and submits an initial parse in the background. The savings are measured as one parser worker and one completed tree released per idle tab; exact RAM bytes are not portably exposed by Tree-sitter/the allocator, so no fabricated number is reported. Covered by FFI suspend/resume tests that preserve text and by tab lifecycle tests with a deterministic clock.

## M4 — LSP (5 weeks)

> The external language server client (`lsp.rs`, `LspManager`, `LspTransport`) was removed in commit `5592010` and replaced by built-in engines. Status notes that mention LSP requests or servers describe the implementation at the time each task was done.

- [x] M4-01 — JSON-RPC transport over stdio (`tokio::process`), `Content-Length` framing, optional traffic log.
  - Status: `lsp::LspTransport` runs one child server with piped stdin/stdout via `tokio::process`, sends JSON `Value`s in `Content-Length` frames, and a reader task forwards JSON-RPC messages/errors/closed to a standard channel that can be polled without blocking the UI. Headers are capped at 16 KiB; truncated headers, missing/invalid `Content-Length`, and invalid JSON become observable errors. `log_traffic` writes incoming/outgoing payloads to the tracing target `galaxy_lsp_traffic`; child stderr is hidden until the lifecycle manager adds server logs. Drop stops the child. Covered by multi-frame decoding, malformed header, and end-to-end `/bin/sh` child tests; request IDs, timeouts, and the lifecycle protocol are M4-02/M4-05.
- [x] M4-02 — `LspManager`: `initialize`/`initialized`/`shutdown`/`exit` lifecycle, one server per (language, root).
  - Status: `LspManager` stores `LspTransport`s keyed by `LspKey(language, root)`, so documents with the same language/root share a child server. `ensure_server` sends the `initialize` request with ID 0; nonblocking `poll` detects its response, sends the `initialized` notification, and publishes lifecycle/message/error/closed events. `shutdown_all` sends `shutdown` then `exit` before dropping the transport stops the child. Executable configuration, initialization options, general request IDs, timeouts, and restart are split into M4-03/M4-05/M4-19. Covered by scripted-server tests: key deduplication, initialize/initialized, and shutdown cleanup.
- [x] M4-03 — Server configuration: detection on `PATH`, settings overrides, `initializationOptions`.
  - Status: `LspSettings` parses the per-language `servers` JSON with `command`, `args`, `logTraffic`, and `initializationOptions`; overrides win over defaults. The default resolver safely looks up executables on `PATH` without shell expansion for typescript-language-server `--stdio`, pyright-langserver `--stdio`, and gopls. Rust does not use an external LSP; `initializationOptions` is passed as-is to the `initialize` request. The UI/editor settings file does not exist until M5-08, so callers currently provide the JSON model directly. Covered by override/options parsing tests and a temporary executable; real server integration is deferred to M4-20.
- [x] M4-04 — Document sync: `didOpen`, incremental `didChange` with debounce, `didSave`, `didClose`.
  - Status: `LspManager` stores a `DocumentSync` per URI and sends `didOpen`, `didChange`, `didSave`, and `didClose` to the shared server. A single `ChangeSet` is sent incrementally with UTF-16 range/rangeLength; multi-cursor edits or bursts within the 50 ms debounce are collapsed into full text so server offsets are always correct. `flush_changes(now)` is nonblocking and is called by the integrator's event loop. Covered by an emoji (2 UTF-16 units) + CJK range test, debounce/full-text fallback, and scripted-server manager lifecycle tests. `LspManager` was later removed together with the external language server client; the built-in engines now receive the current document text directly from `DocumentHandle`.
- [x] M4-05 — Request tracking with IDs, timeouts, and `$/cancelRequest` for stale requests.
  - Status: `LspManager::request` generates monotonic IDs starting at 2 (0 initialize, 1 shutdown), stores the method/deadline, and `poll` publishes `LspEvent::Response` only for IDs that are still pending. `cancel_request` sends `$/cancelRequest` and then discards local state, so late responses are not surfaced; `expire_requests(now)` cancels and publishes `TimedOut`. Notifications remain `Message`, separate from responses. Covered by scripted-server response, single ID/cancel, timeout, and stale request tests. Server retry/restart remains M4-19.
- [x] M4-06 — Diagnostics: underline in the editor, markers in the gutter and scrollbar, Problems panel.
  - Status: live default LSP startup, `publishDiagnostics`, UTF-16 clipping, underline, gutter/scrollbar markers, and a Problems panel with navigation to the diagnostic location are done.
- [x] M4-07 — Hover popover (simple Markdown, highlighted code blocks).
  - Status: `textDocument/hover`, string/MarkedString/MarkupContent parsing, UTF-16 ranges, a popup while the pointer is in the editor, and active-response navigation. Markdown is rendered as simple text; code blocks do not yet have dedicated syntax highlighting.
- [x] M4-08 — Completion: popup, local fuzzy filter, `completionItem/resolve`, basic snippets (`$1`, `$0`).
  - Status: completion requests, item/textEdit parsing, a fuzzy subsequence filter, a keyboard popup, and snippet placeholder removal are done. `completionItem/resolve` is not yet needed for servers that return details directly.
- [x] M4-09 — Signature help.
